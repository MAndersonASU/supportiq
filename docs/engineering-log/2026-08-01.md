# 2026-08-01 — Project bootstrap

## Goal

Stand up the repository and project skeleton before any pipeline work
begins.

## Decisions

- **Project**: SupportIQ — a customer support ticket platform combining a
  data pipeline, an ML triage classifier, and a Claude-powered RAG
  resolution assistant.
- **Scope**: local-first development; a cloud deploy is planned only at the
  end, for the demo.
- **LLM provider**: Claude API, for the retrieval-augmented generation
  layer in Phase 3.
- **Dataset**: Kaggle's "Twitter Customer Support" dataset — real
  brand-support exchanges on Twitter. Preferred over more structured,
  pre-labeled ticket datasets because the raw text requires real parsing,
  labeling, and cleaning work, which better reflects a production data
  pipeline.
- **Repo**: [MAndersonASU/supportiq](https://github.com/MAndersonASU/supportiq),
  public, MIT licensed.

## Completed

- Repository initialized and structured.
- Project layout scaffolded: `src/{data,features,models,ai,serving}`,
  `tests/`, `docs/engineering-log/`.
- `README.md` and `docs/architecture.md` written, describing the
  five-stage pipeline (ingestion → features → ML model → RAG → serving).
- `.gitignore` added (excludes raw/processed data, model artifacts, MLflow
  run directories — data will be tracked separately via DVC once the
  ingestion pipeline exists).

## Next steps

Acquire and scope the Twitter Customer Support dataset, and build the
ingestion pipeline stage (`src/data`): load raw records into a defined
